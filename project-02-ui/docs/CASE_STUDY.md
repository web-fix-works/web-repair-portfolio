# Case 02｜JavaScript UIの改善とアクセシビリティ

**対象サイト：** HELIO Support Center（コンセプトサイト）  
**技術：** HTML / CSS / JavaScript / WAI-ARIA / History API

## 課題とアプローチ

タブ式のFAQでは、クリック時の予期しないスクロール、URLと表示状態の不一致、キーボード操作への未対応が起こりやすくなります。標準のHTMLを起点とし、JavaScriptの読み込みが成功したときだけタブUIを有効にする構成にしました。

- [サイトを見る](../index.html)

## 対応内容

- JavaScript非実行時は通常のアンカーリンクとFAQとして全カテゴリを閲覧可能。
- 初期化後に `tablist` / `tab` / `tabpanel`、`aria-selected`、`aria-controls`、`tabindex` を設定。
- 左右矢印キー・Home・Endキーによるタブ操作と、適切なフォーカス管理。
- `history.replaceState` で表示カテゴリをURLに反映し、不要な画面ジャンプを抑制。
- FAQ検索では表記ゆれを正規化し、結果件数をライブリージョンで通知。
- 印刷前にカテゴリとFAQの全文を展開し、印刷後は検索条件・開閉状態を復元。

## 設計判断

| 判断 | 目的 |
| --- | --- |
| HTMLを先に完成させる | JavaScriptが動作しない場合も重要情報を読み取れるようにする。 |
| タブの操作をWAI-ARIAパターンに沿わせる | マウス・キーボードの両方で操作できる一貫したUIにする。 |
| URLと選択状態を同期 | リロード・直接アクセス・戻る操作で現在の表示を扱いやすくする。 |
| 印刷中の表示状態を一時的に変更 | 検索結果だけではなくFAQ全体を紙面に掲載する。 |

## 確認したい操作

1. タブをクリックしても不必要なスクロールが起きないこと。
2. キーボードで全タブに移動でき、選択状態が更新されること。
3. `#safety` などのURLで選択カテゴリが復元されること。
4. 検索条件を指定して印刷し、終了後に画面の状態が戻ること。
